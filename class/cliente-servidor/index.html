📖 ¿Qué es el modelo Cliente-Servidor?

El modelo cliente-servidor es una arquitectura de software en la que las tareas se reparten entre proveedores de recursos o servicios (servidores) y demandantes (clientes). Es la base de Internet, la World Wide Web, el correo electrónico, las bases de datos y prácticamente cualquier aplicación moderna en red.

En este modelo, el cliente inicia la comunicación solicitando un servicio, mientras que el servidor permanece a la escucha, procesa la petición y devuelve una respuesta. Esta separación de responsabilidades permite escalabilidad, mantenimiento centralizado y seguridad.

🧩 Componentes principales

💻

Cliente

Es el dispositivo o programa que solicita recursos. Puede ser un navegador, una app móvil, un videojuego o una terminal. Inicia la comunicación y espera la respuesta.

🗄️

Servidor

Es el sistema que provee recursos, datos o servicios. Escucha peticiones, las procesa y devuelve respuestas. Suele estar siempre activo y con alta disponibilidad.

🔗

Protocolo

Conjunto de reglas que rigen la comunicación: HTTP/HTTPS, FTP, SMTP, TCP/IP, WebSocket, etc. Definen el formato de los mensajes y el orden de intercambio.

🏗️ Tipos de arquitecturas cliente-servidor

Arquitectura Descripción Ejemplo
2 capas Cliente y servidor directamente conectados. Sencilla pero poco escalable. App de escritorio + base de datos
3 capas Cliente → Servidor de aplicación → Servidor de datos. Mejor separación. Aplicación web con API y BD
N capas Múltiples niveles: presentación, lógica, negocio, persistencia, etc. Arquitecturas empresariales (microservicios)
P2P Cada nodo actúa como cliente y servidor a la vez. BitTorrent, blockchain

⚖️ Ventajas y desventajas

✅ Ventajas

  • Centralización de datos y recursos
  • Mayor seguridad y control de accesos
  • Escalabilidad horizontal y vertical
  • Mantenimiento y actualizaciones centralizadas
  • Reutilización de servicios por múltiples clientes
  • Separación clara de responsabilidades

❌ Desventajas

  • El servidor es un punto único de fallo
  • Cuellos de botella si hay muchas peticiones
  • Costos de infraestructura y mantenimiento
  • Dependencia de la red para funcionar
  • Posibles problemas de latencia
  • Complejidad en la sincronización de datos
